5G PDU Session

Understand how a UE gets a data session and how traffic reaches the user plane.

What is a PDU session?

A PDU session is the logical session used to provide data connectivity between the UE and a data network through the 5G Core. Session management is primarily handled by the SMF, while user traffic is forwarded through the UPF.

Simple flow

  1. UE requests data connectivity.
  2. Core network validates and establishes the session.
  3. SMF selects/configures the user-plane path.
  4. UE receives the required radio and QoS configuration.
  5. User traffic can flow through the UPF.

Useful troubleshooting questions

  • Was the session request accepted?
  • Was the requested DNN/slice information correct?
  • Was a QoS flow established?
  • Did the UE receive the expected radio configuration?
  • Is user-plane traffic actually flowing?

Registration is not the same as data connectivity

A UE can be successfully registered and still have no working data session. Registration establishes the UE's relationship with the network; a PDU session provides the actual data connectivity needed by applications.

Where the SMF and UPF fit

The SMF handles important session-management decisions and configuration, while the UPF forwards user traffic. The UE also needs the corresponding radio configuration so that the data path works end to end.

A useful troubleshooting chain

Follow the chain from UE request → core acceptance → session configuration → QoS flow → radio bearer → user-plane traffic. If the session exists but data does not flow, compare the control-plane result with the user-plane evidence.
