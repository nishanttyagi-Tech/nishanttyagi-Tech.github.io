CHAPTER 01

From EPC to the 5G Core

How MME, S-GW and P-GW became AMF, SMF and UPF, in two steps.

Page 3 / 88

1.1 The 4G core today

In the EPC, the MME handles signalling, mobility and session control. The S-GW and P-GW each do two jobs at once: they take part in the signalling and they forward the user data.

TS 23.401 §4.2
Page 4 / 88

1.2 Step one: CUPS

Release 14 split each gateway in two. SGW-C and PGW-C keep the control part. SGW-U and PGW-U only forward packets. The control part steers the user part over the new Sx interfaces, so user plane nodes can be scaled and placed close to the user.

1.3 Step two: regroup the functions

5G regroups these pieces. The mobility part of the MME becomes the AMF. Its session part joins SGW-C and PGW-C in the SMF. The two user plane gateways merge into the UPF. The HSS becomes UDM and AUSF, and the PCRF becomes the PCF.

TS 23.214 · TS 29.244 · TS 23.501 §4.2 · TS 23.214
Page 5 / 88

1.4 The 5G core as reference points

N1 and N2 carry signalling from the UE and the gNB to the AMF. N3 carries user data to the UPF. The SMF controls the UPF over N4, using PFCP, the same protocol CUPS introduced for Sx.

1.5 The 5G core as services

The control functions no longer need a dedicated interface for every pair. Each one offers services over HTTP/2 and the others call them. NRF, NSSF and NEF are new: service discovery, slice selection and exposure to applications.

TS 23.501 §4.2.3 · TS 29.244 · TS 23.501 §4.2.6 · TS 29.500
Page 6 / 88

1.6 Who does what: NG-RAN and 5GC

The radio side keeps radio resource management and scheduling. The AMF handles NAS security and idle mode mobility. The SMF allocates the UE IP address and controls PDU sessions. The UPF anchors mobility and handles the packets.

1.7 Three changes to remember

The 5G core is the EPC taken apart and put back together: control separated from user plane, mobility separated from sessions, and services in place of fixed interfaces.

TS 38.300 §4.2 · TS 23.501 · TS 23.214 · TS 38.300

CHAPTER 04

Inside the gNB

CU, DU and RU: where the base station is cut, and what F1 and E1 carry.

Page 23 / 88

4.1 The classic base station

A gNB can be one box that holds the whole radio protocol stack, from RRC down to RF. That is simple, but every site then needs the full processing, and sites cannot share it.

TS 38.300 §4 · TS 38.401
Page 24 / 88

4.2 Eight places to cut

3GPP studied eight options for splitting the stack between a central and a remote part. The further right the cut, the more is centralised. Three matter in practice: option 2, option 7 and option 8.

4.3 The 3GPP split: CU and DU

3GPP standardised option 2. The gNB-CU hosts RRC, SDAP and PDCP. The gNB-DU hosts RLC, MAC and PHY. The F1 interface connects them. To the core and to other gNBs the pair still looks like one gNB.

TR 38.801 §11 · TS 38.401 §6.1.1
Page 25 / 88

4.4 What F1 carries

F1-C carries F1AP signalling: interface management, UE context management and the RRC messages, which the DU passes on without reading. F1-U carries the user data in GTP-U tunnels, with flow control so the CU does not overfill the DU.

4.5 Splitting the CU as well

The CU can be split again into a control part and a user part. CU-CP hosts RRC and the PDCP for signalling. CU-UP hosts SDAP and the PDCP for user data. E1 connects the two, and it carries no user data.

TS 38.470 · TS 38.473 · TS 38.425 · TS 38.401 §6.1.2 · TS 38.460
Page 26 / 88

4.6 Fronthaul, midhaul, backhaul

A split gNB needs three transport segments. Fronthaul runs from the radio unit to the DU. Midhaul is F1, from the DU to the CU. Backhaul is NG, from the CU to the core.

4.7 Why the cut position matters

A high layer split is easy on transport: its bitrate follows the user traffic and it tolerates delay. A low layer split needs far more capacity and very low latency, but allows close coordination between cells.

TS 38.401 · eCPRI and O-RAN specifications · TR 38.801 §11.1
Page 27 / 88

4.8 Who hosts what

CU-CP for signalling, CU-UP for user data, DU for the real-time layers and RU for the radio. F1 and E1 are open 3GPP interfaces, so the parts can come from different vendors.

TS 38.401 §6.1 · TS 38.470 · TS 38.460

CHAPTER 05

5G Deployment Options

Six ways to combine the LTE and NR radios with the EPC and the 5G core, and where SA and NSA fit.

Page 28 / 88

5.1 Two radios, two cores

5G brought a new radio, NR, and a new core, 5GC. Each can be paired with the LTE radio or the LTE core, EPC. 3GPP numbered these combinations as options. Options 6 and 8, NR anchored on the EPC alone, were dropped, so six remain.

TR 38.801 · TS 38.300 §4.1 · TS 37.340
Page 29 / 88

5.2 Option 1: LTE as it is

Option 1 is the 4G network as it is: an LTE eNB connected to the EPC over S1. It is the starting point of every migration path.

5.3 Option 3: EN-DC, the NSA launch

Option 3 adds NR without a new core. The LTE eNB is the master node and holds the control plane to the EPC. An NR node, the en-gNB, is the secondary node and adds capacity. This is EN-DC, the non-standalone 5G most networks launched with.

TS 36.300 · TS 37.340 §4.1.2
Page 30 / 88

5.4 Option 3, 3a and 3x

The three variants differ in where user data splits. In 3, the eNB splits it. In 3a, the core sends separate bearers to each node. In 3x, the en-gNB splits it, so the NR node carries the load.

5.5 Option 2: standalone 5G

Option 2 is standalone 5G: an NR gNB connected to the 5G core over NG, with no LTE involved. The 5G core brings network slicing and the service-based architecture.

TS 37.340 §4.2 · TS 38.300 §4.1 · TS 23.501
Page 31 / 88

5.6 Option 5: LTE on the 5G core

Option 5 keeps the LTE radio but connects it to the 5G core. The upgraded eNB is called an ng-eNB and uses the NG interface. The UE needs 5G NAS to use it.

5.7 Option 7: NGEN-DC

Option 7 is dual connectivity on the 5G core with LTE as the anchor. The ng-eNB is the master node and an NR gNB is the secondary node. This is NGEN-DC.

TS 38.300 §4.1 · TS 37.340 §4.1.3
Page 32 / 88

5.8 Option 4: NE-DC

Option 4 turns it around. The NR gNB is the master node and an ng-eNB is the secondary node. This is NE-DC: NR leads and LTE adds capacity.

5.9 The six options side by side

Most operators started with option 3 and are moving to option 2. Options 4, 5 and 7 are in the specifications but rarely deployed. Two NR nodes on the 5G core is called NR-DC.

TS 37.340 §4.1 · TS 38.300 §4.1

CHAPTER 06

Dual Connectivity

One UE, two base stations at once: cell groups, signalling bearers and the three kinds of data bearer.

Page 33 / 88

6.1 One UE, two nodes

In dual connectivity the UE uses radio resources of two base stations at the same time. The master node holds the control plane connection to the core. The secondary node adds capacity. The two nodes talk over X2 or Xn.

TS 37.340 §4.1
Page 34 / 88

6.2 Two cell groups

The cells of the master node form the master cell group, with a PCell. The cells of the secondary node form the secondary cell group, with a PSCell. Inside each group, carrier aggregation can add SCells.

6.3 Control plane: one RRC state

The UE has a single RRC state, set by the master node. Each node still has its own RRC entity. The secondary node writes its own configuration, and the master node carries it to the UE inside its own RRC message.

TS 37.340 §3.1 · TS 38.331 · TS 37.340 §4.2.1
Page 35 / 88

6.4 Split SRB and SRB3

With a split SRB, the master node sends the same RRC message over both radio paths, which protects it when one path is weak. With SRB3, a gNB acting as secondary node exchanges RRC messages with the UE directly, for example its own measurements and reconfigurations.

6.5 Three bearer types

From the UE side there are three kinds of data bearer. An MCG bearer uses only the master cell group. An SCG bearer uses only the secondary cell group. A split bearer has one PDCP and an RLC leg in each group.

TS 37.340 §4.2.1 · TS 37.340 §4.2.2
Page 36 / 88

6.6 Where PDCP sits in the network

On the network side each bearer is terminated in one node: the one that hosts its PDCP and its connection to the core. For a split bearer, that node sends part of the data to the other node over X2-U or Xn-U.

6.7 Carrier aggregation or dual connectivity

Both add carriers, but in different places. Carrier aggregation works inside one node and splits the data at MAC. Dual connectivity uses two nodes and splits at PDCP, so it tolerates a slower link between them. The two can be combined.

TS 37.340 §4.2.2 · TS 38.300 §5.4.1
Page 37 / 88

6.8 Three things to remember

Dual connectivity is two nodes sharing one UE: the master node leads, the secondary node adds capacity, and PDCP is the layer that ties the two paths together.

TS 37.340 §4

CHAPTER 07

Secondary Node Addition

How a UE on LTE gets its NR leg in EN-DC, message by message.

Page 38 / 88

7.1 The trigger

The UE is connected on LTE. The MeNB asks it to measure NR with event B1. When the UE reports an NR cell that is strong enough, the MeNB decides to add an NR secondary node.

TS 36.331 · TS 37.340 §10.2.1
Page 39 / 88

7.2 SgNB Addition Request

The MeNB asks the SgNB to allocate resources. The request carries the bearers to serve, the UE capabilities, the measurement results and the security key for the SgNB, S-KgNB.

7.3 The SgNB accepts

The SgNB admits the bearers, picks the PSCell and reserves radio resources. Its answer contains the NR RRC configuration for the UE, the secondary cell group configuration, packed in a container.

TS 37.340 §10.2.1 step 1 · TS 36.423 · TS 37.340 §10.2.1 step 2
Page 40 / 88

7.4 The UE is reconfigured

The MeNB sends RRCConnectionReconfiguration and puts the NR configuration inside it unchanged. The UE applies both parts and answers Complete. The MeNB then tells the SgNB that the UE has accepted.

7.5 Random access on NR

The UE synchronises to the PSCell of the SgNB and performs random access there. From now on it has two radio links: LTE to the MeNB and NR to the SgNB.

TS 37.340 §10.2.1 steps 3–6 · TS 36.331 · TS 38.321
Page 41 / 88

7.6 Bearer state moves over

If a bearer moves to the SgNB, the MeNB sends its PDCP sequence number status in SN Status Transfer and forwards the buffered data, so nothing is lost or duplicated.

7.7 The core path is updated

For bearers that now end in the SgNB, the MeNB tells the MME the new downlink tunnel address. The S-GW switches the path and sends an end marker on the old one. User data now reaches the UE through NR.

TS 37.340 §10.2.1 steps 7–12 · TS 36.413
Page 42 / 88

7.8 The same procedure on the 5G core

With a 5G core the steps are the same and only the names change. X2AP becomes XnAP, E-RABs become PDU sessions and QoS flows, and the path update goes to the AMF.

TS 37.340 §10.2.2 · TS 38.423 · TS 38.413

CHAPTER 08

The 5G QoS Model

PDU session, QoS flow, QFI and radio bearer: how a packet gets its treatment from the core to the air.

Page 43 / 88

8.1 Three levels

A PDU session carries all traffic to one data network. Inside it, QoS flows are the finest unit of treatment, each with its own identifier, the QFI. On the radio, the gNB packs the flows into data radio bearers.

TS 23.501 §5.7.1 · TS 38.300 §12
Page 44 / 88

8.2 Downlink: marking in the UPF

The UPF classifies each downlink packet with its packet detection rules and writes the QFI into the GTP-U header. The gNB reads the QFI and SDAP places the packet on the right radio bearer.

8.3 Uplink: QoS rules in the UE

In the uplink there are two steps in the UE. NAS-level QoS rules decide which QoS flow a packet belongs to. Then the access stratum decides which radio bearer carries that flow. The gNB passes the QFI on to the UPF.

TS 23.501 §5.7.1 · TS 29.281 · TS 37.324 · TS 23.501 §5.7.1.4 · TS 38.300 §12
Page 45 / 88

8.4 Who gets what from the SMF

The SMF decides the QoS and tells three parties. The UE gets QoS rules over NAS. The gNB gets a QoS profile for each flow over N2. The UPF gets detection and enforcement rules over N4.

8.5 Flows onto radio bearers

How flows map to radio bearers is up to the gNB. Flows with similar needs can share a bearer, and a demanding flow can have one to itself. Uplink packets that match no mapping rule go to the default bearer.

TS 23.501 §5.7.1.2 · TS 23.502 §4.3.2 · TS 38.300 §12 · TS 37.324
Page 46 / 88

8.6 The SDAP header

SDAP is the new layer that does this mapping. Its header is a single octet with the QFI. Two downlink bits switch on reflective behaviour, so the UE can learn its uplink mapping from the downlink packets without extra signalling.

8.7 GBR and non-GBR flows

Every PDU session has a default QoS flow, which is non-GBR and stays for the life of the session. GBR flows are added for traffic that needs a guaranteed rate, and delay-critical GBR flows for traffic with hard deadlines.

TS 37.324 §6.2.2 · TS 23.501 §5.7.2 · §5.7.3
Page 47 / 88

8.8 What changed from 4G

In 4G one EPS bearer meant one radio bearer and one core tunnel. In 5G the core tunnel is per PDU session, the QoS flow is the unit of QoS, and the gNB is free to group flows on the radio.

TS 23.401 · TS 23.501 §5.7

CHAPTER 10

RM, CM and RRC States

Three state machines run in every 5G UE at the same time. What each one tracks, and how they fit together.

Page 56 / 88

10.1 Three state machines

A 5G UE is always in three states at once. RM says whether it is registered. CM says whether it has a signalling connection to the core. RRC says what kind of radio connection it has. The first two are NAS states. The third is a radio state.

TS 23.501 §5.3.2 · §5.3.3 · TS 38.331 §4.2.1
Page 57 / 88

10.2 Registration management

In RM-DEREGISTERED the network cannot reach the UE. A successful registration moves it to RM-REGISTERED, where the AMF holds its context. The UE then refreshes its registration when it moves to a new area and periodically on timer T3512.

10.3 Connection management

CM-CONNECTED means the UE has an N1 signalling connection to the AMF. That connection is made of two parts: the RRC connection on the radio side and the N2 connection between the gNB and the AMF. In CM-IDLE neither exists.

TS 23.501 §5.3.2 · TS 23.501 §5.3.3
Page 58 / 88

10.4 Three RRC states

NR has three RRC states. RRC setup takes the UE from idle to connected. A plain release sends it back to idle. A release with suspendConfig sends it to RRC_INACTIVE, and a resume brings it back to connected.

10.5 What changes in each RRC state

Idle and inactive look alike for the UE: it reselects cells on its own and listens for paging. The difference is in the network. In inactive the gNB keeps the UE context, pages the UE itself, and the core still sees it as connected.

TS 38.331 §4.2.1 · §5.3 · TS 38.300 §7.2
Page 59 / 88

10.6 One UE over time

Follow one UE. It registers and all three states change together. When the data stops, the gNB suspends the UE: RRC goes to inactive, but CM stays connected. When data returns, a resume is enough. After long inactivity everything goes back to idle.

10.7 Why RRC_INACTIVE exists

From idle, getting back to data needs a full setup with the core involved. From inactive, the UE resumes with the context and keys it already has. That saves signalling and time for devices that send small amounts of data often.

TS 23.501 §5.3.3.2.5 · TS 38.300 §9.2.2 · TS 38.331 §5.3.13
Page 60 / 88

10.8 Three things to remember

RM and CM are tracked by the UE and the AMF. RRC is tracked by the UE and the gNB. RRC_INACTIVE is the one state where the radio side and the core side see the UE differently.

TS 23.501 §5.3 · TS 38.331 §4.2

CHAPTER 11

RRC Inactive

Suspend, the RAN notification area, resume and RAN paging: how the gNB keeps a UE on standby.

Page 61 / 88

11.1 Suspend: what the UE is given

The gNB moves a UE to RRC_INACTIVE with an RRCRelease that contains suspendConfig. It gives the UE an identity for its stored context, the I-RNTI, an area to move in, a paging cycle and a timer.

TS 38.331 §5.3.8 · SuspendConfig
Page 62 / 88

11.2 The RAN notification area

The RAN notification area is a set of cells, given as a cell list or as RAN area codes. It lies inside the registration area. Within it the UE reselects cells freely and tells no one.

11.3 Resume at the same gNB

To return to connected, the UE sends RRCResumeRequest with its I-RNTI and a short integrity check. The gNB finds the stored context and answers RRCResume. The bearers come back as they were.

TS 38.300 §9.2.2.3 · TS 38.331 §5.3.13 · TS 38.300 §9.2.2.4.1
Page 63 / 88

11.4 Resume at a different gNB

If the UE has moved, the new gNB reads the I-RNTI to find the last serving gNB and fetches the UE context from it over Xn. After the resume it switches the path at the core and releases the old context.

11.5 RAN paging

The core still thinks the UE is connected, so downlink data simply arrives at the last serving gNB. That gNB pages the UE in its own cells and asks its neighbours over Xn to page in theirs. The UE answers with a resume.

TS 38.300 §9.2.2.4.1 · TS 38.423 · TS 38.300 §9.2.2.4.2
Page 64 / 88

11.6 RNA update

The UE reports in when timer T380 expires or when it enters a cell outside its notification area. It sends a resume request with the cause rna-Update. The gNB can answer with a new suspend, so the UE stays inactive.

11.7 Security at resume

The resume request goes out unprotected on SRB0, so it carries a short MAC-I to prove the UE is genuine. Both sides then derive a fresh key, and everything from RRCResume onwards is ciphered and integrity protected.

TS 38.300 §9.2.2.5 · TS 38.331 §5.3.13.8 · TS 33.501 §6.8.2 · TS 38.331 §5.3.13.3
Page 65 / 88

11.8 Idle and inactive side by side

RRC_INACTIVE moves the standby job from the core to the RAN: the gNB keeps the context, the gNB pages, and the gNB is told when the UE leaves its area.

TS 38.300 §9.2.2 · TS 38.331 §4.2.1

CHAPTER 12

5G Access Control

How a congested network stops access attempts before they are sent: cell barring and Unified Access Control.

Page 66 / 88

12.1 Two mechanisms

When a cell is overloaded, the cheapest request is the one that is never sent. 5G has two tools for that. Cell barring keeps UEs off a cell altogether. Unified Access Control filters single access attempts, by who is asking and what for.

TS 22.261 §6.22 · TS 38.304 §5.3 · TS 38.331 §5.3.14
Page 67 / 88

12.2 Cell barring and reservation

The MIB carries cellBarred, so the UE learns the status before it reads anything else. SIB1 can reserve the cell for operator use or for other use. A UE that finds a cell barred leaves it out of cell selection for up to 300 seconds.

12.3 Who is asking, and what for

UAC describes every access attempt with two things. The access identity says who the subscriber is, for example an ordinary user or a priority service user. The access category says what the attempt is for.

TS 38.331 MIB, SIB1 · TS 38.304 §5.3.1 · TS 24.501 §4.5.2 · TS 22.261 §6.22
Page 68 / 88

12.4 Access categories

The standardised categories cover paging response, emergency, signalling, voice, video, SMS and data. Operators can define their own in the range 32 to 63. For most categories NAS also sets the matching RRC establishment cause.

12.5 What the cell broadcasts

SIB1 lists the barring for each access category as a set of three values: a barring factor, a barring time, and seven bits that say which special access identities are barred.

TS 24.501 Table 4.5.2.2 · Table 4.5.6.1 · TS 38.331 §6.3.2 · UAC-BarringInfoSetList
Page 69 / 88

12.6 The barring check

Category 0, the response to paging, is never barred. A UE with a special identity whose bit is zero is allowed. Everyone else draws a random number. If it is below the barring factor the attempt goes ahead. If not, the UE waits for timer T390.

12.7 NAS classifies, RRC checks

The work is shared inside the UE. NAS maps the request to an access category and hands it to RRC with the access identities. RRC runs the check against the latest SIB1 and reports back. The network is not asked.

TS 38.331 §5.3.14.5 · TS 24.501 §4.5 · TS 38.331 §5.3.14
Page 70 / 88

12.8 Three things to remember

One framework replaces the separate barring schemes of LTE. The operator turns a few values in SIB1, and each UE decides for itself whether to send.

TS 22.261 · TS 24.501 §4.5 · TS 38.331 §5.3.14

CHAPTER 13

5G SA Initial Registration

From the first SSB beam to the first IP packet: cell search, random access, registration and PDU session establishment, message by message.

Page 71 / 88

13.1 Find the cell: SSB

The gNB sweeps SSB beams. PSS and SSS give timing and the physical cell ID. The MIB on PBCH gives the SFN and where to find SIB1. The UE keeps the strongest SSB index. That beam choice decides which PRACH occasion it will use.

TS 38.213 §4.1 · TS 38.331 MIB
Page 72 / 88

13.2 Read SIB1

DCI 1_0 scrambled with SI-RNTI in CORESET#0 schedules SIB1 on PDSCH. SIB1 carries the PLMN list, tracking area code, cell selection thresholds and the RACH configuration. The UE now camps on the cell.

TS 38.331 §5.2.2 · TS 38.304
Page 73 / 88

13.3 Msg1: PRACH preamble

The UE sends a randomly chosen preamble in the PRACH occasion mapped to its SSB. It has no identity on the cell yet. The gNB measures the timing offset. The UE ramps its power on each retry.

TS 38.321 §5.1 · TS 38.213 §8.1
Page 74 / 88

13.4 Msg2: Random Access Response

DCI 1_0 with RA-RNTI schedules the RAR. It gives the timing advance, an uplink grant for Msg3 and a Temporary C-RNTI. The UE computes the RA-RNTI itself from the PRACH occasion it used, and listens inside the RA response window.

TS 38.321 §5.1.4 · TS 38.213 §8.2
Page 75 / 88

13.5 Msg3: RRCSetupRequest

On the granted PUSCH the UE sends ue-Identity and establishmentCause, here mo-Signalling. ue-Identity is ng-5G-S-TMSI-Part1 if the UE has one, otherwise a 39-bit random value.

TS 38.331 §5.3.3.3
Page 76 / 88

13.6 Msg4: RRCSetup

The Contention Resolution MAC CE echoes the Msg3 identity. The UE that sees its own identity has won. RRCSetup configures SRB1. The Temporary C-RNTI becomes the C-RNTI and the UE is RRC_CONNECTED.

TS 38.321 §5.1.5 · TS 38.331 §5.3.3.4
Page 77 / 88

13.7 Registration Request reaches the AMF

RRCSetupComplete carries the NAS Registration Request: type initial, SUCI or 5G-GUTI, UE security capability, requested NSSAI. The gNB selects an AMF and forwards the NAS PDU in NGAP Initial UE Message. The UE starts T3510.

TS 24.501 §5.5.1.2.2 · TS 23.502 §4.2.2.2.2 · TS 38.413
Page 78 / 88

13.8 5G AKA authentication

UDM resolves the SUCI and creates the vector. The AMF sends RAND, AUTN, ngKSI and ABBA. The USIM checks AUTN and the UE returns RES*. The AMF checks HRES* against HXRES*, the AUSF checks RES* against XRES*. K_SEAF and K_AMF follow.

TS 33.501 §6.1.3.2
Page 79 / 88

13.9 NAS security

The AMF selects the NAS ciphering and integrity algorithms and replays the UE security capabilities to stop bidding down. Security Mode Complete carries the full Registration Request in the NAS message container. From here NAS is ciphered and integrity protected.

TS 24.501 §5.4.2 · §5.5.1.2.2 · TS 33.501 §6.7.2
Page 80 / 88

13.10 UE context and AS security

The AMF registers in UDM and fetches subscription data. Initial Context Setup gives the gNB K_gNB, the UE security capabilities and the allowed NSSAI. The gNB activates AS security with keys derived from K_gNB. It can also ask for the UE radio capabilities.

TS 23.502 §4.2.2.2.2 steps 14–21 · TS 38.413 · TS 38.331 §5.3.4
Page 81 / 88

13.11 Registration Accept

Registration Accept assigns the 5G-GUTI, the TAI list, the allowed NSSAI and 5GS network feature support, such as IMS voice over PS. RRCReconfiguration sets up SRB2. The UE answers Registration Complete. It is registered, but still has no data path.

TS 24.501 §5.5.1.2.4 · TS 38.331 §5.3.5
Page 82 / 88

13.12 PDU Session Establishment Request

The UE asks for a PDU session: session ID, type, SSC mode and PCO, with DNN and S-NSSAI in the UL NAS Transport. The AMF selects an SMF. The SMF reads subscription data, gets policy from the PCF, selects a UPF, allocates the IP address and sets up N4.

13.13 Accept and user plane

The SMF returns the Accept with the UE IP address, QoS rules and Session-AMBR, plus N2 information with the QoS flows and the UPF tunnel. The gNB sets up the DRB and returns its tunnel endpoint. The SMF updates the UPF over N4, and data can flow.

5G NR Bands, NR-ARFCN and Bandwidth

Where a 5G carrier sits in the spectrum, how its channel number works, and how wide it can be.

14.1 Two frequency ranges

NR works in two frequency ranges. FR1 runs from 410 MHz to 7.125 GHz. FR2, the millimetre wave range, runs from 24.25 to 52.6 GHz. Release 17 extends it to 71 GHz.

14.2 Operating bands

A network does not pick any frequency it likes. It uses operating bands, each with a number, the letter n in front, and a duplex mode. n28 and n1 are FDD. n41 and n78 are TDD. All FR2 bands are TDD.

14.3 Band combinations

Bands can be combined, for carrier aggregation or for dual connectivity with LTE. Only combinations listed in the specification are allowed. The phone reports the ones it supports in its UE capability message, and the network configures only those.

14.4 The channel number: NR-ARFCN

The exact carrier position is given by a channel number, the NR-ARFCN. Frequency = offset + step × (channel number − its offset). The step is 5 kHz below 3 GHz, 15 kHz up to 24.25 GHz, and 60 kHz above that.

14.5 Try it on a real log

Channel 154570 × 5 kHz gives 772.85 MHz, in band n28. Channel 641760 is above 600000, so we use 15 kHz steps starting at 3 GHz. The result is 3626.4 MHz, in band n78.

14.6 Channel raster

Not every point of the global grid can be used. Each band has its own channel raster. In n41 it is 15 kHz, so only every third point of the 5 kHz grid is a valid carrier position. A coarser synchronization raster tells the phone where to search for the SSB.

14.7 Channel bandwidth and guard bands

The channel bandwidth is not all usable. Resource blocks fill the middle and a guard band is left on each side. At 15 kHz spacing, a 50 MHz channel carries 270 resource blocks: 48.6 MHz, with about 700 kHz of guard on each side.

14.8 Maximum bandwidth per subcarrier spacing

The widest channel depends on the subcarrier spacing. In FR1, 15 kHz reaches 50 MHz and 30 kHz reaches 100 MHz with 273 resource blocks. In FR2, 120 kHz reaches 400 MHz. Each is about 3200 subcarriers, which fits a 4096-point FFT.

14.9 Five ideas to read any log

To sum up: range, then band, then channel number, then raster, then bandwidth. With these five ideas you can read the frequency part of any 5G log.
